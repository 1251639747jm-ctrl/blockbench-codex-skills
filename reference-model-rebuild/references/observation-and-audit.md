# 自主观察与审计方法

用于收到新参考、首次建立建模依据，以及续作时补充或修正观察。执行者必须实际看图并写出本次分析；不依赖预先存在的细节说明、审计清单或工作记录。

## 先看图，再形成记录

对每张原参考使用图像查看能力，先确认全图内容与尺寸，再对重要区域做可回溯的裁切或放大。记录文件路径、参考 ID、可辨认的视角和原图尺寸。工具无法显示图像时，文件存在、OCR文字或旧报告不能代替视觉观察。

按三个尺度观察，范围随对象变化：

| 尺度 | 主动观察的内容 |
|---|---|
| 整体 | 姿态或装配状态、外包比例、轮廓转折、重心、轴线、主要体积和识别性特征 |
| 部件与层次 | 哪些是独立体、哪些是同一壳面的转折；内外覆盖、连接点、前后关系、重复与对称 |
| 局部 | 端点、拐角、曲率变化、凹口、开孔、宽度/截面变化、搭接边、厚度线和局部色面 |

从整体分区逐区查看，覆盖所有实际可辨认且影响还原的特征。不能只看正面或中心区域就跳过侧后、边缘和下方，也不能把模糊像素拆成大量虚构细节。

观察时主动区分：

- 部件边缘、表面图案、投影阴影、反光和环境遮蔽。暗线不必然是缝，亮边不必然是倒角。
- 同一物体在不同视图中的出现与不同物体的重复。通过轮廓、位置、挂点和遮挡共同判断，不能只凭颜色近似。
- 明确的几何不对称与光照造成的左右明暗差异。被遮挡的一侧按对称补全时，标记推断依据。
- 可见厚度与无法确定的隐藏深度。正面宽度不能自动推出前后尺寸。

## 用户标注、历史记录与真正测量的边

用户最新的明确纠正优先于旧审计的结构假设。例如挂点被纠正后，要重新追踪整条连接路径；不能只把起点名称改掉，保留原来的错误几何。旧文档中的许可、暂停、待办和“通过”属于当时的任务与版本，不自动构成当前指令或当前验收。

收到用户画线或问题截图时，先用图像内容定位到原图或对应模型版本，保存可复现的裁切、比例与坐标映射。将线条宽度和抗锯齿计入读数不确定性；某高度只画了一侧，就只记录那一侧。不能移动局部模型截图来迎合标线。

测量前明确边界对象：

- 可见白色面宽、完整袖体轮廓和含扣件的外包宽度可能是三条不同的边。
- 侧图中两腿的联合投影宽度，不是单条腿的深度；后视受头发遮挡的袖边不能直接描成完整袖边。
- 头顶装饰和头发的共同轮廓，不是被覆盖的裸颅边界；刘海相邻折点未必属于同一束。
- 部件出现次数、物理零件数、审计条目数和 Cube 数分别记录。多片围成一条带，不代表有多条带。

对曲线可记录端点、段长、屏幕方向和相邻转折，但**图像切线角不是三维欧拉角或曲面法线**。短段的角度对读点误差很敏感；端点误差已接近段长时，保留定性转折，不输出虚假的精确角度。内外轮廓分别描点，不跨越不相连部件计算“接缝”。

## 编写参考观察记录

没有记录文件就主动创建；也可在已有项目记录中新增对应部分。文件名可为 `参考观察.md`，具体形式不重要，实际观察内容必须存在。

记录应包含原始参考索引、整体比例判断、主要结构依赖，以及以下部件/特征表。表头是结构示例，所有内容由执行者根据当前图片填写：

| 字段 | 需要写出的实际内容 |
|---|---|
| 部件 ID | 本项目内稳定唯一的标识；同一部件的多个审计属性共用该 ID |
| 特征或关系 | 具体的边界、转折、厚度线、连接方式或覆盖关系 |
| 证据位置 | 参考 ID、对应视图、原图坐标/区域或可明确定位的描述 |
| 可见形状 | 宽窄变化、轮廓路径、截面、朝向、根部与末端等实际观察 |
| 跨视图对应 | 其他图中的同一部件、可见部分、遮挡者，以及不能对应的原因 |
| 证据等级 | 明确可见／合理推断／无法确定，附依据与仍待验证的内容 |
| 实现依赖 | 应先完成的基础体积、挂点或邻接层；可采用的可编辑表示 |

图像尺寸或像素测量只有实际读取/测量后才能写成数值，近似读数标注量级与不确定性。相机未校准前，读点属于图像空间观察，不应提前声称对应世界深度已经准确。

隐藏区域采用能与所有已知视图一致的简洁结构，并保留可编辑性。证据不足不是增加精巧内部结构的理由，也不是将可见区域跳过检查的理由。

## 由观察记录建立还原审计

参考观察说明“图里是什么”；还原审计说明“当前模型与图里的要求相差什么”。两者可以放在同一文档的不同部分，但不能混淆事实和实施结果。

没有模型时，先将可验证特征转成审计项目，状态为“未建模”。有模型后，实际打开对应投影/叠图，再填写差异。初始空白表不算完成审计，旧模型的历史问题也不能未经查看就作为当前版本的问题。

每项审计至少记录：

| 字段 | 用途 |
|---|---|
| 审计 ID / 部件 ID | 将问题关联到实际可编辑对象或局部结构 |
| 参考要求与证据 | 具体可见特征及对应参考区域 |
| 当前版本与视角 | 被检查的工程版本、相机版本及投影图 |
| 实际偏差 | 哪条边、哪个点、哪种遮挡关系错了；方向和有依据的量级 |
| 优先级 | 对比例、识别度、轮廓或后续搭接的影响 |
| 修正动作 | 需要改变的顶点、局部尺寸、厚度、朝向或挂点 |
| 复核结果 | 修改后各相关视图的变化、是否影响邻接部件、证据图路径 |
| 状态 | 未建模／待修／通过／受遮挡／未验证 |

优先解决主体比例、主要体积和标志性轮廓，再解决局部转折、层间关系和小细节。不要让大量低影响项的完成数量盖过少数明显的结构错误。

“受遮挡”针对该视图内无法直接观察的内容；应继续寻找其他视图证据，不能把整件部件从审计中免除。“通过”需要实际完成本阶段可观察约束的复核，不以渲染文件生成成功代替。

## 观察冲突与迭代

新视图、局部放大或一次叠图可能推翻初始部件划分。此时更新观察记录及依赖关系，注明新依据，再修模型；不要为了维护旧表而忽略图像证据。

参考可能来自不同姿态、版本或绘制方法。记录具体冲突位置；在已有主参考明确时按其确定主体，并标出次参考中不可直接对照的区域。只有冲突阻止确定关键造型且现有信息无法消解时，才向用户索取必要选择，其他观察与准备继续进行。

每轮工作记录由执行者更新，至少写清：

- 实际查看了哪些参考区域和模型投影，新发现或修正了什么。
- 本轮修改了哪些部件，对应哪些审计条目。
- 哪些视图已复核、结果如何、哪些仍未验证。
- 保存的工程与相机版本、当前对象统计、下一项具体修改。

交付记录应包含真实观察和验证结果。不能仅交空模板、虚构条目数、复制其他项目的坐标，或让用户补写本应由执行者完成的细节分析。
