# 统一 Minecraft 像素语言

实体与物品共用此文件；具体纹理预算由模型尺寸和用户风格决定，不强制所有 PNG 都是 16×16。

## 固定空间尺度，再绘制

先选一个代表性面，声明可见像素的模型单位尺寸 p，或密度 d=1/p。默认先比较原版尺度感，再按项目的 16x、32x 等风格约定调整；不要给整类模型强制一个 d。

对未缩放的轴对齐 cube 面，设几何两边长为 L_u、L_v，UV 跨度为 Δu、Δv，UV 坐标域为 U×V，**单帧**像素尺寸为 W×H：

`d_u = |Δu| × W / U / L_u`，`d_v = |Δv| × H / V / L_v`。

- 例如几何宽 8、UV 宽 8、UV 域宽 16、单帧宽 16，则为 1 texel/模型单位；几何宽改成 16 而 UV 不变，密度就减半。
- 处理 90°/270° 面 UV 旋转时交换几何边对应关系；负 UV 跨度取绝对值。父级缩放、rescale、任意面变形与非标准 UV 另行算变换后的长度，不套局部公式。
- 16×8192 的竖向动画条若单帧为 16×16，是 512 帧，不是每帧 8192 像素高。大图集中的小 UV 岛也不等于高清材质。
- texel 密度只是线索：重复 2×2 同色像素看起来是一大格；纯色取样不能代表材质的可见像素尺度。必须查看实际色块与几何共同形成的画面。
- 主体、口沿、底部、内壁、外壁、顶面、附属物分别抽样；同一材质优先保持接近一致的密度。特效可有明确的尺度例外，但不能无理由忽粗忽细。

放大投影时同时规划新的逻辑像素数量和 UV。仅等比拉大卡片会把像素一起放大；若需保持密度，应重绘到匹配尺寸。不要用双线性插值放大来补“细节”。

## 像素质感不是模糊或马赛克滤镜

- 在目标逻辑网格上设计连贯的色块、阶梯边、留白和少量明暗层次。采用最近邻查看和缩放；低清是减少有效细节，不是把图像弄糊。
- 拒绝写实火焰照片、细丝烟雾、柔焦星芒、抗锯齿细线与锐利方块主体混搭。程序化图案同样检查是否过密、过碎。
- 硬边火焰、符号和星点优先使用清楚的透明/不透明轮廓；方块云允许有限级别的半透明，但半透明不能自动制造毛边与模糊晕染。
- 在黑、白、棋盘格背景检查透明外缘。查残留底色、孤立像素、非设计所需的光圈；透明区域 RGB 脏色也可能在特定采样方式下露边。不能把有意的云雾半透明误报成抠图残边。
- 发光设计也保留块状边界：高亮核心和少量分档外缘优先于大片柔光。

## 可视验收

先区分纹理底色和预览光照。原生编辑器的方向阴影可能使白毛正面偏灰、侧面更暗；检查贴图本色和中性环境下的轮廓，再决定是否改材质。允许调整预览环境光，但保留几何/UV/贴图一致并说明渲染条件；调整 shader 预览不代表游戏里已实现自发光、bloom 或动态照明。

使用同一相机、同一模型比例和最近邻采样比较前后；放大局部可查像素，但还要看实际手持/GUI 或实体游戏距离下是否清楚。先关特效看主体，再逐层打开。无法获得实际渲染时，明确只是纹理/结构检查，不能宣称风格与遮挡已验收。

## 纹样、做旧和改色版本

“太乱”先减少竞争的纹样、对比和碎点，保留主纹与材质分区；“太素”补回有作用的层次，不能在全删花纹与重新密铺之间来回摆动。同材质的胸甲、臂甲、腿甲应协调，但不因此抹平内外衣甲层次。

做旧先确定磨损位置与尺度：边缘、活动处、接缝及大面各有分工，疏密不规则。血渍若是外来飞溅，应是少量有方向的点迹/短拖痕，覆盖可能被溅到的部位但不抢主体；不是集中一大块，也不是有规律的像素噪声。亡灵将军的“干净版/做旧加血渍版”共用造型基线，只做要求中的两个材质版本。

配色变体先按身体、腹部、毛发、角、爪、眼睛等建立语义色板和保留项，再局部重映射；别对整图无差别调色。参考中的蓝光、轮廓光与环境照明不一定是材料本色，更不等于“白龙就是冰霜龙”。用户只改体色时保留已认可的眼睛与瞳孔；数量与主题遵循本次要求。

白色材质用克制但可辨的鳞片/层次区分体块，既不能脏灰斑驳，也不能清理成纯白无细节。黑色材质仍需可读的明度层次。最终重新打开输出 BBModel，核对内嵌贴图、外部文件和面引用一致；不能外部 PNG 已换色而工程仍加载旧图或白图。
