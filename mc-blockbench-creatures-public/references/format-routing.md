# 按「转换项目」的实际保真度选择制作方法

用户明确要求：这里判断的是 Blockbench 自带「转换项目」能否保留工程内容，**不是**游戏导出格式是否相似。不要用“都能导出 JSON”或“运行时不同”直接判断编辑器转换有损/无损。

## 形体分类与工程格式分开

人模、非人型生物、物品道具决定造型、比例与运动链；工程格式决定允许使用哪些编辑功能。共用造型方法，按实际会丢失的功能分支，不给每种格式复制一整套人体/生物教程。

| 用户称呼 | 本次 Blockbench 实际格式 ID | 制作时关注 |
| --- | --- | --- |
| Java 模组版实体 | `modded_entity` | 本机格式要求 Box UV、单贴图，不支持 Mesh/Locator；本次转换确实改变了逐面 UV |
| 基岩版实体 | `bedrock` | 共用 cuboid/骨骼/数值关键帧；额外保留 Bedrock binding 等专属字段 |
| 通用模型 | `free` | 可用 Mesh、多贴图等更宽能力；若将来要转格式，先限制到目标支持的功能集合 |
| GeckoLib 实体 | `geckolib_model` | 当前项目常用入口；不假设其他格式能保存 GeckoLib 专属属性/事件或反向保留其专属字段 |
| Animated Java 实体 | 本次插件为 `animated-java:format/blueprint` | 专用 Blueprint、Variant、Texture Slot 和显示节点单独处理；当前测试未得到可用的转换结果，不能承诺通用模型直接无损转入 |

上述 ID、能力和异常是版本化证据，不是永远不变的接口。首次换版本或插件后，检查实际注册格式与转换结果。

## 用户说「做一个 XXX 的实体」时

1. **用户明确指定形式**：直接使用指定的工程格式；共通造型/骨骼方法继续复用。
2. **修改已有工程**：读取实际 `meta.model_format` 或专用工程格式，保留当前类型，不根据实体名称偷偷切换。
3. **在现有项目新建**：沿用同类资产与项目约定。新建格式沿用所在项目同类资产和用户指定的导出链，不预设 GeckoLib 为所有项目默认。
4. **没有目标环境且不同路线会影响建模能力**：先用已知需求缩小范围，仅澄清会影响资产选择的一点；不凭“实体”二字自动选 Bedrock、Generic 或 Animated Java。
5. **用户明确要求可迁移**：写清要迁移到哪些形式，按其共同支持的功能制作，并用实际小样验证。单一 cuboid 图集、稳定骨骼层级与已验证的数值关键帧可作为起点；若包含 Modded Entity，先按该格式的 Box UV 能力设计，不能先自由逐面画贴图再承诺无损转换。

不默认把 Generic 当万能中间格式。能从某格式转入 Generic，不意味着 Generic 的任意功能都能转回。只在本次资产使用的功能已经验证可保留时复用制作方法。

## 怎样判断“无损”

先说明保留对象：几何与可见面、贴图像素与面绑定、UV 及旋转、骨骼层级/pivot、关键帧时间/数值/插值、表达式/事件、专属节点和属性。

对稳定副本使用菜单「转换项目」（默认创建副本）或确认与菜单一致的转换 API，记录版本与格式。`Codecs.project.compile({raw:true})` 的结果可能含共享数组；立刻 JSON 序列化/深拷贝冻结快照，不能等转换结束后才保存所谓“之前”。检查三层：

1. **工程数据**：按 UUID 匹配节点；不能只比 cube 数量。检查丢节点、UV 模式改变、贴图重绑定、丢非空字段、动画轨道变化。
2. **实际表现**：固定相机/光照比较真实模型；在关键姿态之间采样父变换后的姿态与包围盒，不能只比局部欧拉角。
3. **可恢复性**：转回原格式，并额外做“保存为临时工程 → 重新打开 → 转回”的检查。内存中仍残留的字段不等于保存后能恢复。这里保存的是编辑器工程，不调用游戏导出器。

格式标识、空默认字段、预览时延迟创建的无关键帧 animator 与实际内容变化分开记录；不把测试工具自身的初始化变化误报为动画丢失。没有覆盖的功能标为未验证。通过一个样例只说明该样例的已检查功能，不能宣布两个格式对所有资产都无损。

## 2026-10-24 本机取证

环境：Blockbench **5.2.2**；GeckoLib 插件 **4.2.5**；Animated Java **1.11.0**。普通样例取自项目小凶许的稳定副本（16 个 cube、18 个 group、1 个 4 秒 idle）；压力样例加入一个 Mesh、一个 Locator、第二张贴图的面绑定及面 UV 旋转。普通动作检查 0、0.175、1.4、3.25、4 秒。

除 GeckoLib 源例外，起始格式样例通过克隆该工程并以相应格式载入来构造；它们是转换功能小样，不能冒充每种格式真实制作流程的完整代表。特别是测试 06 包含浮点 Box UV，Modded Entity→GeckoLib 有 UV 数值变化，不据此推断所有原生实体都会受损。

| 「转换项目」路径 | 实测结果 | 对制作方法的影响 |
| --- | --- | --- |
| GeckoLib → Bedrock → GeckoLib，普通样例 | 过滤空默认/预览初始化差异后，核心几何、层级、贴图、UV、实际关键帧一致；5 个姿态的矩阵和 cube 包围盒差异为 0 | 这个受限功能集可共享方法；不能外推表达式/专属字段也无损 |
| GeckoLib ↔ Generic，普通样例 | 核心数据与 5 个采样姿态保持；少量空分组元数据属于默认字段差异 | 纯 cuboid 骨骼制作可以复用，仍保留目标格式约束 |
| GeckoLib → Modded Entity → GeckoLib，普通样例 | 16 个 cube 的逐面 UV 被改为 Box UV；回转未自动恢复，原生截图可见贴图变化；几何及所检查姿态未改变 | 若目标包含 Modded Entity，UV 方法从一开始分支；不能只看模型形状判断无损 |
| Generic → Bedrock / GeckoLib，压力样例 | Mesh 删除，使用第二张贴图的面被重新绑定到第一张；转回 Generic 不恢复 | 不能把 Mesh、多贴图制作方法直接用于承诺可转换的资产 |
| Generic → Modded Entity，压力样例 | Mesh、Locator 删除，UV 模式/贴图绑定改变 | 直接按目标能力制作，或明确转换需重建的部分 |
| Bedrock 非空 bone binding → GeckoLib → 保存重开 → Bedrock | binding 不再保留 | 连共通骨骼路线也必须保留格式专属属性边界 |
| Generic / GeckoLib → Animated Java | 本机插件转换出现读取 `default` 的 TypeError；新配置、仅一个 Animated Java 插件、实际菜单“创建副本”路径仍复现 | 当前版本/环境不列为已验证无损路线；不伪造转换成功，不为证明兼容去修改原模型或插件 |

本次未验证所有方向、所有插件专属节点、复杂表达式/事件与每种插值；也未做游戏运行时验证。新需求涉及这些功能时补充针对性小样，而不是把未验证填写成“不支持”或“无损”。

本项目有效证据位于 `tmp/skill_preview_20261024/conversion_verified/`：`cases.json`、`summary.json`、转换前后/回转工程、`reopen_cases.json`、`aj_clean_menu_test.json`；同条件 UV 对照图为 `tmp/skill_preview_20261024/conversion_uv_comparison.png`。旧 `conversion/` 的前后快照受共享数组影响，已废弃，不作为量化差异依据；独立的 AJ 菜单错误记录已复制到有效目录。这些项目路径用于本次溯源，技能迁移到其他项目时不能假定存在。

参考：[Blockbench 格式表](https://blockbench.net/wiki/blockbench/formats/) 仅作能力线索，[Animated Java 官方安装说明](https://animated-java.dev/docs/getting-started/installing) 用于版本与插件来源。上表转换结论来自本机编辑器实测，不由导出格式推断。
