# 时间网格、修改保护与运行时交接

## 源资产保护

明确本次允许改几何、骨骼、UV、贴图、哪些动画及哪些阶段。保留用户最新修改和满意的部位；不要用历史文件覆盖整份 bbmodel 来修一个动作。

修改前保留可恢复副本。改父子关系、pivot、模型整体尺寸后要检查所有受影响动作；不要只在静止绑定姿态下验收。

## 生成工程的对象标识

UUID 标识对象，不标识显示名称。脚本生成时，骨骼和 cube 即使同叫 `ear_left`，也必须使用不同 UUID；可用 `bone:ear_left`、`cube:ear_left` 等带类型的稳定键生成。骨骼声明与 outliner 对该骨骼的引用共享 UUID 是正常的，不能把引用误报成重复对象。

一旦出现多个部位掉到原点、耳朵/手脚异常聚集，先检查元素与骨骼之间的 UUID 冲突、outliner 解析和 mesh 父级，再检查 pivot；别直接改坐标补偿。审计器会检测声明重复与元素/骨骼交叉冲突。

可用独立 Blockbench 配置目录和本地调试连接做原生读取、渲染及导出；保留用户正在编辑的实例。软件/API/插件版本以实际环境为准，不把某次端口、安装路径或 shader 字符串写成固定接口。

## 时间吸附

读取当前动画的 snapping 和任务约定。Minecraft 20 tick/s 不等于每个项目必须把所有动画量化到 20 FPS；用户明确要求对齐 tick 时才按 0.05 秒网格处理。

先报告离轨帧及轨道，再做授权修改：

- 区分浮点误差和真正离轨，使用合理容差比较 `time × fps` 与整数。
- 保留 pre/post data point、插值、表达式及静态姿态；不能把未理解的 Molang 当 0。
- 吸附可能把两个不同姿态合并到同一通道同一时刻，先解决冲突，不静默删前一个。
- 关键帧不能无意越过总长度，事件轨与结束标记要一起核对。
- 稀疏化比较末端世界轨迹、接触时段和表现，不仅比较总键数或局部欧拉角。

用户要求把一个挥击压缩至三 tick 时，定位核心发力段并保留其前后摇；不要把整个动画压缩成三 tick。过渡总时长变化必须通知代码侧更新事件与伤害窗口。

## 导出

先确认资源格式与实际导出链，输出可编辑 bbmodel 和任务需要的 geo/animation JSON/纹理。导出后比对动作名、时长、骨骼名与变化范围，检查没有将用户其他新动作回退。

允许自行导出时使用已验证的工具或等价转换；没有 Blockbench 软件连接时明确是文件处理，不声称已在软件中播放。用户要自己导出时在源资产完成后交接，等待确认，不自行继续依赖旧导出做运行时改动。

### GeckoLib 的原生脚本导出

在 Blockbench 5.2.2 + GeckoLib 插件 4.2.5 的 `geckolib_model` 工程中，已验证以下调用；插件版本与游戏侧 GeckoLib 库版本分别记录。其他版本先核对实际接口。

```javascript
const geometry = Codecs.bedrock.compile({raw: true});
const names = Animation.all.map(animation => animation.name);
const animations = Animator.buildFile(null, names);
```

该插件会读取动画导出的第二个参数，直接调用 `Animator.buildFile()` 会报 `arguments[1][0]` 相关错误。需要导出部分动作时显式筛选 `names`。通过 CDP 执行时可将导出对象返回给 Node 写文件；当前渲染器上下文没有 `require`，不要在其中依赖 `require('fs')`。

## 交给运行时代码的契约

提供实际方块尺度、模型前向轴、基准点、全局缩放、骨骼/部位名称、动画总时长、准备/接触/收势窗口、进入/循环/退出关系和哪些动作含根位移。

强调代码侧必须做的配套项：例如头部姿态改动需要更新吐息实际方向，尾巴降低需要同步接触几何，俯冲撞地使用新的基准点。只导出动画并不代表 AI、伤害与 OBB 已自动更新。

## 单一时序与位移契约

当前任务若涉及模型、特效、声音、判伤、道具离手或多角色演出，为相关事件维护同一份时间表：动画/阶段名、秒或 tick、动作标志、触发点及资源版本。改停留、提速、出场节奏或配乐对齐后，同步所有受影响事件；不要只改动画让剑气先于挥剑，或让墓龙出场与始皇指剑错开。记录事件与姿态关系，避免用一个过时固定 tick 套全部新版本。

明确整体平移/朝向的拥有方。项目采用原地模型时，由代码完成整体位移与大幅转身；局部骨盆、四肢与道具动画仍保留。其他情况按实际要求决定。动态落点另注明锁定时刻，不让动画隐含的路径与代码追踪互相争夺。

道具/分身从模型移交独立对象时，检查同一帧的世界变换、比例、可见性与后续控制者；角色与龙协同表演时记录相对位置和各自状态，不能只看两个独立预览。

## 预览与最终文件

区分设计图、实际模型预览、游戏实机录像。预览使用当前交付文件及正确父变换、插值、材质；相机要覆盖完整武器轨迹和大范围龙身，同时提供关键局部。用户要实机录像时，不能交离线渲染并称实机。不要为验证资产擅自修改用户存档、IDE 启动参数或自动进存档配置；优先沿用项目已有测试入口，隔离确需的测试状态。

程序生成可移植的内嵌贴图工程时，不附带无意使用的外部 `texture.path`。在 Blockbench 5.2.2 中，存在的路径会让贴图以 `link` 模式加载，重复覆盖同路径后可能仍显示旧图；检查导入后的纹理模式和实际像素。仅当目标确为内嵌 `bitmap` 时移除该路径，或从新的 data URL 显式刷新；用户有意保留的外部链接不做此处理。

同路径贴图修订后的预览若出现错位，先用全新专用 Blockbench 配置重开最终文件核对，再决定是否需要改资产；仅检查纹理 error=0 或源文件哈希不变不能排除旧图缓存。原生截图比较应比较 RGB 或全部通道，RGBA 差图的透明 alpha 可能使默认 getbbox() 漏报颜色差异。

交付前重读最终 BBModel 和配套文件，核对保存的字节确实包含最后一次修改，嵌入纹理/外部纹理与引用匹配。声明最新源资产和导出包；历史备忘录标明被哪份新约定覆盖。用户自行导出时尊重其等待节点，不拿旧 JSON 开始后续代码接入。
