# 几何、纹理和连接

## 简练而有辨识度

用主轮廓、倾斜面、正负空间和纹理分工。斜块的作用是改变形体走向，不是加一块突出的板遮住原来的方体。先看不带贴图的轮廓，再看低分辨率贴图能否补足表情和材质。不要从另一只角色沿用头身比、五官、附肢或配色。

先判断主要识别特征：长吻生物强调吻部与脑壳层次；短吻兽强调额头、鼻梁和面颊；鸟类强调喙、眼眶与颅顶；人形强调面部比例与肩胯；甲壳或机械生物强调外壳分区与关节负空间。眼眶斜面可以有外展与俯倾，但不能使眼睛从正视图消失。需要口腔的角色要一起检查口腔颜色、牙齿位置与闭口咬合；没有牙齿或胡须的物种不要为了套模板而添加。

先用一个主块和少量辅助块建立每个大部位。只有在轮廓、关节活动、材质厚度或动画挂载确实需要时才拆块。圆润感来自截面比例、嵌套关系、斜面和贴图协同，不来自逐像素堆 cube。

## 独立物件的对称

对重复包饰等局部件，先确定物件自身的中心轴和需保持的上下端点，再从同一轮廓生成镜像。独立模型按该格式的编辑中心摆放；并排展示偏移不作为镜像轴。分别检查变换后的顶点、贴图透明轮廓和像素行，用正交正反面核对，不能只凭透视图或左右包围盒判定对称。修正外展量后复查鞘口等相邻装配空间。

## 嵌套体积与接缝

腹部、胸甲、软组织或内层结构应嵌入外层体块并露出适当厚度；颜色分界不能代替实体连接。模型在初始姿态无缝，不代表弯曲后无缝。按最大预期活动范围检查关节内外侧、翼根、肩胯和长身段的外弧。

需要增加连接长度时，先检查两侧端面、枢纽和截面中心。优先在接缝内加略微内缩的重叠段，或有控制地延长现有段；避免大面积共面外表面导致闪烁。不要随意改变整条身体长度、头身比或增加无用骨骼。修改后验证连接块确实同时搭接相邻两节；OBB 相交只能排查实体断开，还必须看表面是否仍露出黑洞或明显台阶。

初始姿态、动画姿态和游戏坐标是不同概念。抬高整体模型到脚掌着地时，也要同步检查根位移和动作高度。几何变化后重算需要的碰撞尺寸和相对枢纽偏移，不能假设旧表仍有效。

## 像素卡片与 UV

实体的毛发、羽缘、鳍膜、须、火焰及适合平面表现的薄片装饰可通过少量有层次的像素轮廓卡片表现：成束、留白、方向清楚。不同部位分别设计，不把同一张贴图机械铺满所有位置。牙齿、指甲、羽毛或薄片结构使用卡片时仍要有正确的根部、朝向与运动归属。

具有体积的方块云雾应按体积设计，不因“可用卡片”就退化成一张烟雾照片；物品效果另见 item-effects.md。

零厚度卡片将对应局部轴的 from/to 设为完全相等；薄但非零的盒子仍是两张分开的表面。正反面数量按当前格式、材质背面设置和导出器决定，不预设所有卡片只启用一个面。目标分别渲染正反面时，在同一零厚度 cube 的两个相对面绑定合适 UV；目标用单面材质双面渲染时可只保留需要的面。用正、背、斜视和实际导出核对，不靠复制第二张重合卡片修补消失。爪甲等单尖结构还要区分“薄片从某角度变窄”和“缺失”；相交卡片会产生不同方向的双尖时，应保留符合实体弯曲方向的主片，而非增加横片。不要自动删除用户有意保留的面；静态检查只提示。

羽层贴合同时处理根部、末端和整个卡片法线；只把中心线移到翼面上、宽度方向仍保留原角度，会继续相穿。增加密度时先沿共同翼面错开长短和起点，不把覆羽沿深度拉成悬空的平行层。厚度来自必要的承重结构，羽纹与尖缘由贴图承担。

图集整理后，对每个实际可见面检查纹理引用、坐标域、越界和采样区域的非透明像素；全部落空必须定位，部分透明可能正是毛羽轮廓，不能简单填满。按目标格式计算有效 UV，再和保存重开的结果比较：源文件写有逐面 UV，不代表强制 Box UV 的格式会使用它。可用 [audit_uv_coverage.py](../scripts/audit_uv_coverage.py) 辅助检查。

保持原有 UV 和纹理资产的身份。导出时核对面朝向和上下表面的 UV 翻转；用实际导出格式/项目代码验证转换约定，不靠记忆套用。放大或拉长 cube 后检查像素密度、拉伸和纹理方向。

## 眉眼是结构问题，不只是改眼睛宽高

反馈“憨、忧郁、笑眯眯、没威严”时，先在正视、斜前和侧视拆看眉骨倾向、眼窝深度、眼裂轮廓、内外眼角、瞳孔/高亮位置以及额部和毛发遮挡。先找具体成因再局部修改，不反复只调一张眼片的高宽或角度。

要做内凹眼窝时，让周边额骨/颧部包住眼部并保留可见开口；不能贴两片外凸金属板冒充眼睛，也不能把整个眼片埋到头里。倾斜眉眼须兼顾侧脸，不能正面凶而侧面下垂、遮没。瞳孔要在实际距离可辨，不是一根无宽度线，也不能大到改变角色气质。黑龙无瞳、青白龙有瞳、始皇纯金发光眼分别是角色选择，不互相继承。

## 分清 UV 重叠、几何共面与引用错误

相邻旋转块即使中心和角度不同，也可能因相同宽度而让侧面处于同一平面。白色尾节实例中，静帧接近正常，摆动时交叠侧面出现条纹闪烁；改为有意的粗细过渡、内缩接头或去掉确实不可见的重叠面，再检查插值帧。不要只靠随机微移或换光照掩盖重叠。

UV 岛重叠可能是有意复用纹理；不能看到重叠就全部拆开。画面闪烁先检查重复/共面的外表面与透明层深度；花纹拉伸查 UV 与几何比例；白模或贴错图查纹理引用、内嵌 source、外部 path 和导出映射。每种问题在对应层修复，不把任意偏移 0.01 或旋转所有面写成通用解法。

## 代码生成细长段的角度顺序

Blockbench 5.2.2 的 cube 原生旋转顺序实测为 `ZYX`。把沿局部 +Y 的细长块连接端点时，设差向量 `(dx,dy,dz)`、长度 `L`，可用 `rx=asin(dz/L)`、`ry=0`、`rz=atan2(-dx,dy)`，转换成度，并以起点为 pivot；不要套用 XYZ 的公式。沿 +Z 的身段可用 `rx=-asin(dy/L)`、`ry=atan2(dx,dz)`、`rz=0`。其他版本先查实际顺序。

用原生 world matrix 检查变换后的段尾与下一段根部是否一致，再看画面中的粗细搭接。创建 cube pivot 和 group origin 时分别复制坐标列表；组装平移若共享可变列表，会重复移动同一个枢轴，造成局部正常而整模肢体散开。
