# 传动、发力和稀疏动画

## 连续传动

用沿运动链变化的相位、延迟和幅度表现力的传递，不让所有骨骼同相摆动。可在世界空间设计目标姿态，再转换为父骨骼相对旋转；必须同时处理枢纽、根位移和附属结构的位置。头部或其他活动部位是根骨骼时，单独动作要检查是否意外拖动整只角色，必要时在下一级骨骼补偿。

长身或多节角色要求长弧时，按弧长分配切线角度：总转角约 π/2、中心线长度 L 时，理想半径约 L/(π/2)。沿多个身体段平滑分配转角，俯视检查中心线和头尾切线；不是“根部旋转 90° 就完成四分之一圆”。在需要 90° 朝向的姿态附近，检查欧拉角分支与插值，避免等价姿态的 180° 翻转造成跳动。

按结构选择发力链：二足动作先确定支撑脚与骨盆重心；四足动作协调肩胯和步态相位；翼行动作由胸背带动翼根再到翼尖；鱼形或蛇形动作沿躯干向尾部传递；机械结构体现关节限位、惯性和驱动来源。混合生物可以组合规则，但必须有一个清楚的主推进方式。

保持完整的动作阶段：快速起势、后续传动、必要的维持、受控回正和尾部收势。幅度和频率按角色体量选，不把迅猛误做成突然折叠或持续颤动。

## 接触与趾节

有足角色为每只脚定义支撑、推进、摆动和预落地阶段；按腿的相位驱动需要活动的趾、蹄、爪、脚掌或机械关节。支撑期接触面稳定，推进期由后缘或趾端完成发力；离地后适度放松，落地前准备接触。小幅末端旋转也会被长肢放大，先从小角度开始，再看实际轨迹。

按每个末端的真实结构设置屈曲轴，不能对所有趾、翼指、鳍条或触手机械使用同一世界轴。反向趾或拇趾仍应有正常关节结构。检查真正的承重面，不要让装饰尖端成为唯一支撑点。

在稀疏关键帧之间采样检查，而不是只检查关键帧时刻。先通过调整已有姿态、缓入缓出或拟合接触轨迹稳住脚；不要简单把整只模型抬高来掩盖脚滑或穿地。小幅脚跟离地是蹬地动作，整片脚掌无意悬空不是。

## 状态与编辑

对于持续转弯等不定时行为，提供 enter → loop → exit；loop 应可无限重复。基础动作和过渡至少在指定相位首尾相接。若 loop 有动态起伏，任意相位退出通常需控制器做短混合；说明混合条件和哪些代码没有提供。需要专用移动/待机过渡且在用户交付范围内时，分别处理两个方向；只要求新增行走时不自动增加额外过渡片段。倒放可作起点，但还要看制动发力和动作传递是否合理。

关键帧遵循当前项目吸附约定；明确采用 20 FPS 时才按 frame = round(time × 20)、time = frame / 20 处理。吸附前检查同通道时间冲突，不能静默合并不同姿态。区分预览播放采样率与编辑时间轴吸附率。减少“时间点数”和减少“所有骨骼键数总和”不是同一件事；新增必要关节轨道后总数可能上升，不能宣称总量一定更少。

保留非零静态姿态的必要键，删除确实冗余的键。在简化前后比较端点、转角、足部路径与接触，不只比较欧拉角数值误差。骨骼父变换会放大很小的局部角度差。

## 检查边界

静态审计脚本只检查数据和时间轴，不执行完整 FK、UV 渲染、碰撞或游戏控制器。渲染器必须使用实际模型、父子变换、cube 自身旋转及正确插值；不要用示意图冒充交付模型预览。素材未做游戏内实测就明确说明。

## 分阶段改时序，复用真实姿态

先标出准备、主挥击、停留、回收和事件锚点。用户要延长“拔剑后停留”，就在完成姿态后加停留，不能把拔剑过程整体拉慢；要求加速某一爪击时，不连带改未授权的另一个爪或前后摇。同步更新所有依赖该阶段的时刻、结束标记和导出长度。

复用已认可动作时，以最新文件的实际通道和阶段为准：裁取指定一击并重定时，保留骨骼初始偏置与正确武器朝向；不要照名字重建、把三连整段复播，或从旧备份回退用户手改帧。

衔接从真实源状态开始验证，包括 guard→counter、移动→攻击、循环任意相位→退出。按动作性质选择短混合或专用过渡；打击段的爆发不能被长混合冲淡。模型能平滑插值不代表脚接地、衣甲无穿插或游戏已连上控制器。
