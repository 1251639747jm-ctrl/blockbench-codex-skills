# 局部攻击修复、双手接触与身体跟随

用于攻击、持械动作修改及“牵着别处乱动／只有手臂在动”的问题。先按当前请求划分允许变化的动作、时间段与骨骼，保留修改前快照；不要把一次攻击修复扩成整套动作重写。

## 数据保留与实际姿态分别验证

`diff_bbmodel.py` 验证保存数据的编辑范围。更改父级、pivot 或默认姿态后，即使其他动画 JSON 一字未变，其世界姿态仍可能改变：用真实编辑器采样修改前后相同时间，比较保护动作中的支撑点、头部、武器等实际世界变换。若局部姿态能解决问题，避免以全局改父级或默认姿态绕开它；确需变更结构时要保留保护动作的实际结果。

被修改关键帧的影响不一定止于其时间点。样条邻键、切线和插值会影响前后区间；在允许时间段边缘、主击前后和非关键帧时间采样。不要只比较被编辑键，或把手腕归零当作恢复了正确姿态。

## 双手形成一套接触约束

声明每个阶段谁控制武器、两手分别接触哪个局部握点、何时抓住和放开。以握点变换和手掌内侧位置检查距离、方向、指腹围合以及肩—肘—腕连接；手骨原点相等只能说明两个点重合，不能证明手指包住了柄。

接触标记本身也需要验证。先用原放松指节的弯向、拇指位置、掌背/掌心和手骨默认朝向确定真实掌侧，再放握点；不能因为题目或旧脚本给了一个点，就把手翻到背侧追它。制作指节后查看开手→半握→闭合的侧面近景，确认四指向掌心收拢、拇指对握；左右手不能直接照抄旋转轴或符号。包围一个点的反向拳仍是失败。

持械前后手的顺序也属于动作设计。按参考和招式确认哪只手靠武器前端、哪只手靠后端，不把骨骼归属或任意局部坐标当成握法。若标记与真实握法冲突，保留旧证据并明确修正约束，不隐瞒改评分点，也不为保数值继续做错误姿势。

肩—肘—腕位置解出来后仍有肘平面与前臂轴转的选择。检查握姿朝向是否被全部塞进腕部，造成近似翻腕或折腕；把掌心朝向、前臂轴转与肘部弯向一起处理，再检查握点和指节。不能仅凭骨长未变就声称手臂姿态自然，也不要用某个模型的 Euler 角阈值代替实际姿态判断。

采样握住期间的完整轨迹和关键帧之间的姿态，不只对齐起止帧。采样时刻若与烘焙键完全重合，会漏掉帧间误差；加入偏移或非关键帧时刻，并记录实际采样集合。辅助手的目标来自武器当前世界变换；解算或手工调整必须同时考虑上臂、前臂、腕和真实可达范围。不要把手腕大幅平移、拉长手臂或把整个躯干挂到武器下，以此冒充握住。制作 IK 如需烘焙，只交付导出链实际支持的轨道，并复查烘焙后的插值。

现有放松手没有指节骨时，按需求增加必要的局部可动结构并保留原有姿态；不通过静态改弯手指破坏其他动作。新增骨骼、重挂元素也属于修改范围，需检查旧动作的实际姿态。

## 区分三种“跟着动”

| 关系 | 观察重点 |
| --- | --- |
| 结构继承：手与握持武器、关节下游 | 应随父级变换；检查连接是否断开，不能把所有继承都判为串动 |
| 有意协同：支撑、骨盆、胸腔、视线、另一只手 | 应服务于蓄势、发力和收势；不能仅按“有多少骨骼有键”评分 |
| 次级反应：披风、羽缨、饰物 | 根据惯性与材质有适当延迟/回收；整片随胸腔刚性转动不等于已经有次级运动 |

判断错误牵连时，检查实际祖先链；必要时只在临时内存姿态中扰动一条手臂，看保护的头、髋、脚或独立附件是否被结构性带走。此探针只检查层级依赖，不能替代完整表演。左手跟随双手武器可能是有意约束，不因出现相关轨迹就判错。

判断僵硬时，同时看局部相对变化与世界变化：零局部键不等于世界静止，有局部键也不证明发力合理。先看支撑→肩髋→攻击端的先后、重心与脚底，再看衣摆/羽缨的响应。需要重心转移的攻击还要检查膝髋是否承接发力，不能只靠腿僵直换取低滑步数值。不要为了“全身会动”给全部骨骼叠同相正弦，或让本应稳定的支撑脚滑走。死亡保持、冻结等有意静止保留。

先确定站姿再编发力：需要分脚支撑时，展示站距、脚尖、膝盖与重心的关系；单纯把骨盆降低或并腿屈膝不等于建立了支撑。参考教程须区分正例和错误演示，并记录具体时间段；不要把讲解中的错误倾身照搬为动作。数值达标而用户指出姿态错误时，记录视觉失败并先修姿态，不能用低握点误差或低滑步反驳。

## 取证工具与结果边界

用 `bb_review.mjs` 做同相机全身和握持近景；`bb_motion_probe.mjs` 在空的专用 Blockbench 实例中采样原生骨骼矩阵、局部变换和指定局部点。例：

```powershell
node scripts/bb_motion_probe.mjs --port 9250 --model '<稳定快照.bbmodel>' --animation '<动作名>' --fps 40 --spec '<握点定义.json>' --out '<probe.json>' --plugin '<geckolib.js>'
```

spec 的 `points` 项为 `{"name":"握点","node":"骨骼名或UUID","local":[0,0,0]}`。local 是**该原生 mesh 相对 pivot 的坐标**，不是模型文件全局坐标；先在静态实际模型核对点的位置。全部骨骼自动采样，`elements` 可另外列元素名/UUID。`perturb` 为 `{"node":"骨骼","rotation_degrees":[0,5,0]}`，只在采样内存中临时叠加，不保存工程。

阈值按角色尺度、握柄尺寸和请求设定，不能把某个模型的绝对数值变成所有资产标准。矩阵、接触距离、相位统计用于定位与回归，不给审美自动打合格分。最终查看完整攻击和插值中的近景，分别报告保存数据保留、原生姿态验证和视觉判断；没有游戏验证就不宣称运行时混合已通过。
