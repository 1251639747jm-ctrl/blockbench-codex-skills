# Minecraft Blockbench：人模、非人型生物模、物品道具模

按资产类型选择制作分支，共用需求分析、造型、贴图、按需动画与原生验收流程。文件格式按用户目标和项目导出链选择。

## 1. 选择本次分支

| 类型 | 判断依据 | 先读 | 边界 |

| --- | --- | --- | --- |

| **人模** | 人类、类人角色、人形 Boss；主要依人体肩胯、手臂和双腿表演 | [humanoids.md](references/humanoids.md) | 包括人形亡灵、傀儡；两足鸟兽不因“两条腿”自动归入人模 |

| **非人型生物模** | 兽、龙、鸟、虫、鱼、无肢、植物、机械、元素及混合生物；按自身形态运动 | [creatures.md](references/creatures.md) | 不把所有生物套成中国龙，也不默认添加人类关节 |

| **物品道具模** | 武器、法器、卡牌、持有物、摆件；重点为物件本身 | [items.md](references/items.md) | 先区分 Java 静态/贴图动画与 GeckoLib 等骨骼道具；不要求步态、呼吸和接地 |

混合任务按资产拆分：人物持长枪时，人模负责握持和身体动作，道具负责枪形与材质；五行牌嵌入角色工程时，道具设计仍适用，展开和显隐则遵循实际骨骼导出链。独立 Java 物品与实体化形态分别交付，不假定一个文件能自动通用。

创建工程、判断实体形式或使用「转换项目」时，先读 [format-routing.md](references/format-routing.md)。人模/生物模决定造型，工程格式按实际转换保真度决定功能分支；不按导出扩展名推断无损。新建格式按用户目标和所在项目选择，不预设所有项目都使用 GeckoLib。

读取 `.bbmodel` 的 `meta.model_format`、elements、groups/outliner、textures、animations、display，以及项目实际导出与加载代码。`java_block` 本身不能区分方块和物品；分组、空目标和“会动”也不证明存在可导出的骨骼动画。保留用户选定格式，不擅自转 GeckoLib 或把实体烘焙成海量物品几何。

## 2. 在参考和当前版本上收敛

- 从用户原始参考、后来明确选中的方案、最新手改资产建立基线；区分用户原图、AI 设计稿与实际模型渲染。设计稿不能替代原参考，更不能冒充已实现的模型三视图。

- 新建或大改时，先确定可用 cuboid/卡片/像素材质实现的轮廓、部位比例和层次。写清主要宽高深、相对比例、风格特征与本次验收点；已有局部修正无需重走完整设计流程。用户只要设计时停在设计；已授权制作时自行推进各阶段，不反复索要批准。

- 沿时间顺序处理反馈：后来明确纠正的要求覆盖对应旧要求，其余仍有效。保留用户已经改好的姿态、UV、材质和满意部位。只改眼睛、火焰或配色时，不重置整头、整套动画或几何。

- “憨、忧郁、竹竿、像板子、僵硬”等反馈先落到可观察原因：轮廓、比例、遮挡、朝向、材质或时序，再动手。 用户说明“谁盖住谁、哪里连到哪里、哪部分保留”时，把这些相对关系写成这轮改动目标；检查改的是关系本身，而非只改某块宽高。对“整体选 B、局部用 C”先确定 B 为形体基线，再按授权采用 C 的局部方法；不能用局部评价推翻整体选择。每轮用同视角对照参考和上一版；效果倒退时回到指定基线，再重施仍有效的改动，不能在两个极端间只调参数。

- 保留可恢复版本。在已授权的模型制作/修改中，用户指出具体缺陷，查证后应继续完成局部修复、验证及文件交付；不能只解释原因或承认错误就结束。用户明确只要分析、讨论或要求停止时按其指令处理。按项目约定把过程脚本、备份和预览放在工作目录，正式资产目录保留清晰的最终入口。要求只做两个变体就只交付两个，不凭角色名字追加主题。

## 3. 共用造型与像素规则

新建或整体风格被否定时，先读 [造型语言与局部构建](references/style-language.md)。先按参考重新构建关键局部并检查，再完成整模。按图从零制作时不把已有模型的几何、骨骼、UV 或像素当作新建成果；用户要求修改现有模型或明确授权素材复用时保留对应资产。

**MC 造型优先，再取原角色的识别特征。** 跨漫画/动漫改编时，先用少量主块建立好看的原版尺度轮廓，再选择值得保留的头身比、配色、标志物和表情。毛束、五官、甲片纹样优先判断能否由贴图表达；不是每个画出来的部位都要拆成实体。细节多、cube 少或检查通过，都不等于视觉合格。用户否定整体风格时重做主形，不继续给被否定的轮廓补零件。

角色名称不决定表情。用户补充图片可能只是说明表情范围，不自动代表要复制该图的哭脸/怒视/姿态；结合用户文字与多张实际参考选择默认状态。截图未显示的武器刃头、背面或下半身标为设计补全，不声称完全还原。

修改形体、接缝或 UV 时读 [geometry.md](references/geometry.md)；处理像素密度、配色、材质变体时读 [pixel-style.md](references/pixel-style.md)。

先用少量主块锁定轮廓、长宽深和负空间；斜块应改变结构走向，嵌套体块应表达真实厚度。不要逐像素堆 cube、用外壳补丁掩盖错误体型，或靠堆装饰补救比例。毛发、须、羽缘、布边等按厚度与运动需要选卡片或体块。

纹理负责适合平面表达的纹样和材质；“简化”保留识别特征和层次，不等于全删花纹。以实际观看尺寸比较上下、内外、主体与附属物的世界空间像素大小；图集尺寸、单帧尺寸、有效色块与像素密度分别检查。

## 4. 需要骨骼动作时

人模、生物及骨骼道具按需读 [animation.md](references/animation.md)；角色“僵硬、缺少活性”再读 [model-motion-design.md](references/model-motion-design.md)。Java 纹理动画执行物品分支。

攻击局部修复、双手持械或“手臂带着其他部位乱动／身体僵住”时，读 [combat-contact-review.md](references/combat-contact-review.md)，分别验证接触、世界姿态保留和有意的全身配合。

- 沿真实运动链设置父子关系和连接处 pivot；独立活动或挂载需要才加骨骼，但不因“精简”删除必要的手指、翼膜、口器或尾节。改层级、尺寸、枢纽后检查所有受影响动作。

- 先检查准备、发力、接触、跟随、收势的关键姿态和世界空间轨迹，再补次级动作。活性服从角色状态；冻结、死亡保持等有意静止不强加摇摆。不能以全身同相抖动代替运动传递。

- 使用用户认可动作作运动基准时，复用其真实姿态、轨迹与节奏。只取一段就准确裁取该段；不要重写一个相似名称的动作声称已经复用。

- 先明确模型局部动作与游戏整体位移/转向的控制权。按所在项目明确采用原地动画还是根位移动画。不要清空沉髋、脚步、手部等局部 position，也不要让两端重复应用位移。

- 保留可编辑关键姿态。读取现有 snapping，明确要求 20 FPS 时才用 0.05 秒网格；制作采样率不等于交付键密度。删键前后比较末端轨迹、接触和姿态，不只比键数或欧拉角。无统一的每轨 3–5/9 键上限。

- 不定时状态按需要拆进入/循环/退出；完整表演可保留长动作。过渡检查真实前后状态及任意循环相位切换，不把瞬时挥击统一柔化。控制器混合不能自动修正穿插、脚滑和错误关节。

## 5. 验收与交付

缺少当前任务必要工具时，先按 [tool-setup.md](references/tool-setup.md) 从官方来源安装并验证，再继续；已有工具直接复用，按分支安装。

需要可重复的真实模型多视图、动画采样或版本对照时，读 [native-review.md](references/native-review.md)，使用 `scripts/bb_review.mjs` 与 `scripts/review_report.py`。优先检查已有连接；采集使用专用实例和稳定文件快照，保留相机、采样时间和源文件指纹。工具成功不等于视觉验收。

导出、吸附、版本保护和模型/代码契约读 [asset-handoff.md](references/asset-handoff.md)。

用户要求只改局部并保留其他资产时，读 [local-edit-diff.md](references/local-edit-diff.md)，用 `scripts/diff_bbmodel.py` 比较修改前后的几何、骨骼、UV、贴图像素与动作；按请求声明允许范围，不把范围检查通过当成握持或视觉合格。

1. **结构**：检查格式、纹理引用、骨骼、轨道和动作名称/时长。骨骼资产可运行 `python scripts/audit_bbmodel.py <模型> --fps <本次吸附率> --report <报告>`；Java 物品运行 `python scripts/audit_item_bbmodel.py <模型> --report <报告>`，需要像素解码时加 `--pixels`。先读报告含义，不按提醒自动删面或删键。

图集裁剪、去重、重排或格式变更后，可运行 `python scripts/audit_uv_coverage.py <模型> --report <报告>` 检查有效面的有色覆盖与越界；它会提示本机 Modded Entity 的强制 Box UV 差异。透明轮廓和部分透明不自动算错误，仍需原生重开核对。

2. **画面**：从实际交付模型渲染正、侧、背、俯视及相关局部，保持相机、尺度和灯光可比。正常观看距离核对轮廓、眼神、持械与遮挡。用户要三视图时交付真实模型三视图。

3. **运动**：看完整循环/招式与插值中的接触时刻；核对关节、毛布连接、脚掌/趾甲、武器方向、循环接缝和前后状态。程序采样补充实际回放，静态报告不证明视觉合格。

4. **交接**：给可编辑 BBModel 和任务需要的配套导出。重新读取最终文件，核对嵌入纹理与导出资源一致；几何、骨骼、动画有配套变化时一同交接。明确文件检查、Blockbench 回放和游戏实测分别完成了什么；工具未连接就不能声称已在软件中检查。

本技能负责资产。OBB、战斗 AI、粒子音效触发、着色器和状态效果由代码侧接入；运行时联动按使用者的项目工具和代码流程处理。交付尺度、前向、挂点、时序、接触窗口与位移归属，不宣称改模型已自动修好判伤。
